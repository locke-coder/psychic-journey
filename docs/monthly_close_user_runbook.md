# Monthly Close User Runbook

## 1. Purpose

이 문서는 월마감 영업실적 예측툴을 운영자가 사용하는 순서를 정리한다. 이 툴은 사용자가 직접 입력한 영업일정, 마감일 여부, 일별 목표, 일별 누적 실적을 기준으로 Forecast, Scenario, History/Backtest, Excel 리포트, 보고문을 생성한다.

## 2. Usage Order

1. 승인된 접속 경로로 앱을 연다.
2. Public URL에서는 샘플 또는 익명화 데이터만 사용한다.
3. 기준월을 선택한다.
4. 기준일을 선택한다.
5. 입력 데이터와 검증 메시지를 확인한다.
6. Forecast 결과를 확인한다.
7. Scenario 결과를 확인한다.
8. History/Backtest 결과를 참고한다.
9. 필요한 경우 Excel 리포트를 재생성한다.
10. 보고문을 복사하거나 공유하기 전에 보안 기준을 확인한다.

## 3. 기준월 선택

- 분석하려는 월을 기준월로 선택한다.
- 입력 데이터의 날짜 범위가 기준월과 일치하는지 확인한다.
- 입력표에 없는 날짜를 임의로 생성하지 않는다.
- 월 목표는 기본적으로 일별 목표 합계로 계산된다.

## 4. 기준일 선택

- 기준일은 현재까지 확정된 누적 실적을 기준으로 선택한다.
- 기준일까지의 누적 실적은 계산에 필요하다.
- 기준일 이후 누적 실적은 blank일 수 있다.
- 샘플 데이터 사용 시 기본 기준일이 실제 누적 입력 마지막 날짜보다 뒤이면 validation guard가 표시될 수 있으므로, 누적 실적이 입력된 날짜를 기준일로 선택한다.

## 5. 입력 및 데이터 확인

입력 데이터에는 아래 컬럼이 필요하다.

- `date`
- `day_name`
- `business_day_no`
- `is_close_day`
- `close_type`
- `sales_target_daily`
- `recognized_target_daily`
- `sales_actual_cum`
- `recognized_actual_cum`
- `memo`

확인 원칙은 아래와 같다.

- 사용자는 누적 실적만 입력한다.
- 툴은 누적 실적 차분으로 일별 실적을 계산한다.
- 누적 실적이 감소하면 warning이 표시될 수 있다.
- 취소, 조정, 철회 반영 여부는 운영자가 입력 근거로 확인한다.
- `memo`에는 개인 또는 계약 식별 정보를 넣지 않는다.

## 6. 마감일 여부 입력 원칙

- 마감일은 반드시 `is_close_day` 컬럼으로만 입력하고 판단한다.
- 요일, 날짜 패턴, 월말 여부로 마감일을 자동 추론하지 않는다.
- `day_name`은 화면 표시용이며 계산 판단에 사용하지 않는다.
- `close_type`은 마감 성격 설명에 사용하되, 마감일 여부의 최종 기준은 `is_close_day`다.

## 7. Forecast 확인

Forecast 화면에서는 월마감 예상실적과 목표 대비 상태를 확인한다.

- F1은 기준일까지의 누적 달성률을 잔여 목표에 적용한다.
- F2는 직전 2개 완료 마감회차 실적률을 사용하며, 부족하면 F1로 fallback한다.
- F3은 마감일과 비마감일 실적률을 나누어 잔여 목표에 적용하며, 부족하면 F2 또는 F1로 fallback한다.
- `target_status`, `target_variance`, `surplus_to_target`를 함께 확인한다.
- 예측값은 입력 데이터 품질에 직접 영향을 받으므로, 기준일과 누적 실적 입력 상태를 먼저 점검한다.

## 8. Scenarios 확인

Scenario 화면에서는 목표 미달 또는 초과달성 상태별 운영 전략을 확인한다.

- 목표 미달이면 P1/P2/P3 잔여 목표 보정전략을 확인한다.
- 목표 초과 예상이면 O1/O2/O3 초과달성 운영전략을 확인한다.
- `CAPACITY_LIMITED` 상태는 목표 달성이 가능한 것처럼 해석하지 않는다.
- `recommended_action`은 운영 판단 보조 문구이며, 최종 실행은 승인 절차에 따른다.

## 9. P1/P2/P3 해석

- P1은 기준일 이후 모든 잔여일에 목표 상향액을 배분하는 전략이다.
- P2는 기준일 이후 잔여 마감일에 우선 배분하는 전략이다.
- P3는 기준일 이후 잔여 비마감일에 우선 배분하는 전략이다.
- P2 또는 P3 대상일이 없으면 `NOT_APPLICABLE` 또는 fallback 상태를 확인한다.
- cap 초과로 재배분이 불가능하면 `CAPACITY_LIMITED`를 확인하고 목표 달성 가능으로 보고하지 않는다.

## 10. O1/O2/O3 해석

- O1은 목표 유지와 안전버퍼 확보를 우선하는 전략이다.
- O2는 초과 추세를 상향 목표 또는 추가 성과 포착으로 전환하는 전략이다.
- O3는 취소, 철회, 미수, 품질 리스크를 방어하는 전략이다.
- O1/O2/O3는 초과달성 상태의 운영 선택지이며, 단순히 `NO_GAP`으로 대체하지 않는다.
- 초과달성 전략도 실데이터 승인과 공유 제한을 동일하게 따른다.

## 11. History 및 Backtest 확인

- History/Backtest 화면에서 과거 예측 흐름, 모델별 차이, 실제 확정값 반영 여부를 확인한다.
- 입력 기준월과 기준일이 Forecast 화면과 동일한지 확인한다.
- Backtest는 모델 품질을 점검하는 보조 정보이며, 운영 확정 수치로 단독 사용하지 않는다.

## 12. Excel 리포트 재생성

Excel 리포트가 필요할 때만 재생성한다.

- 재생성 전 입력 데이터가 승인된 샘플 또는 익명 데이터인지 확인한다.
- 실데이터 기반 재생성은 사전 승인이 있을 때만 수행한다.
- 필수 시트는 `Summary`, `ScenarioGrid`, `DailyRevisedTargets`, `CloseCycle`, `Validation`, `ReportText`다.
- `ScenarioGrid`에서 P1/P2/P3 또는 O1/O2/O3 전략 표시를 확인한다.
- Excel 파일 공유 전 민감정보 포함 여부와 공유 범위를 다시 확인한다.

## 13. 보고문 복사 및 공유 주의

- 보고문은 입력 데이터와 예측 결과를 바탕으로 생성된 운영 보조 문장이다.
- 외부 공유 전 실데이터, 고객 식별 정보, 계약 식별 정보가 포함되지 않았는지 확인한다.
- Public URL 또는 승인되지 않은 외부 채널에 실데이터 기반 보고문을 공유하지 않는다.
- 운영 의사결정 문서에 붙여 넣을 때는 기준월, 기준일, release commit, 데이터 익명화 여부를 함께 기록한다.

## 14. 실데이터 보안 주의

- 실데이터는 Private 배포 또는 승인된 내부 접근 통제에서만 사용한다.
- `.streamlit/secrets.toml`의 실제 내용을 열람, 출력, 복사하지 않는다.
- 테스트, 샘플, 교육 자료에 실제 고객명, 전화번호, 주소, 계약번호, 주민번호를 넣지 않는다.
- 데이터 업로드 전 승인자와 운영자가 파일 내용을 확인한다.
- 장애 또는 의심 상황에서는 추가 업로드를 중단하고 운영 책임자에게 보고한다.

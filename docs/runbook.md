# 운영 Runbook

## 공통 운영 원칙

이 문서는 `AGENTS.md`의 산식, 입력규칙, 보안규칙, 테스트규칙을 우선 적용합니다.

- 이 저장소는 입력주도형 영업 마감 예측툴입니다.
- 사용자가 영업일정, 마감일 여부, 일별 목표, 일별 누적 실적을 직접 입력합니다.
- 툴은 요일이나 날짜 패턴으로 마감일을 자동 추론하지 않습니다.
- 마감일 판단은 입력 파일의 `is_close_day` 컬럼만 기준으로 합니다.
- 입력표에 없는 날짜를 임의로 생성하지 않습니다.
- 기준일 이후 누적 실적은 비어 있을 수 있습니다.
- 일별 실적은 사용자가 입력하지 않고, 누적 실적의 차분으로 계산합니다.
- 현재 월 입력 파일을 새로 업로드하면 해당 누적 실적을 최신 기본값으로 등록합니다.
- 원본 입력 파일은 절대 수정하지 않습니다.
- 고객명, 전화번호, 주소, 계약번호 등 개인정보 또는 민감정보는 저장하지 않습니다.
- 금액 단위는 기본적으로 억 원입니다.
- 금액 표시는 소수점 1자리, 달성률 표시는 `%` 소수점 1자리입니다.

## 매일 운영 순서

1. 당일 운영 입력 파일을 준비합니다.
2. `date`, `business_day_no`, `is_close_day`, 목표, 누적 실적 컬럼을 확인합니다.
3. 기준일까지의 누적 실적이 선택 metric에 모두 입력되어 있는지 확인합니다.
4. 기준일 이후 누적 실적은 blank로 두어도 됩니다.
5. Streamlit 앱을 실행합니다.
6. 입력 파일을 업로드하거나 샘플 데이터를 로딩합니다.
7. 새 현재 월 입력 파일을 업로드한 경우, 앱이 업로드 파일의 누적 실적을 최신 기본값으로 등록했는지 확인합니다.
8. 과거 월 누적 데이터가 있으면 `1-1. 과거 월 누적 데이터`에서 선택 업로드합니다.
9. metric, 기준일, forecast model, provision strategy를 선택합니다.
10. validation errors와 warnings를 먼저 확인합니다.
11. errors가 없을 때만 KPI, 3x3 시나리오 매트릭스, 선택 시나리오 상세, 다음 마감 필요실적을 해석합니다.
12. 과거 월 데이터가 업로드된 경우 같은 영업일차 과거 중앙값과 현재 누적 달성률 차이를 함께 해석합니다.
13. 필요하면 Excel 리포트를 다운로드해 보고 자료로 사용합니다.

## 업로드 최신값 등록 정책

현재 월 입력 파일을 업로드하면 앱은 이전에 저장된 실적 기본값보다 업로드 파일의 `sales_actual_cum`, `recognized_actual_cum`을 우선합니다. 이후 `2. 입력 수정` 표에서 운영자가 보정한 값은 다시 최신 기본값으로 저장되어 다음 화면 계산의 기본값으로 사용됩니다.

샘플 데이터는 저장된 실적 기본값을 확인하는 데 사용할 수 있지만, 새 현재 월 업로드 파일의 값을 덮어쓰는 기준으로 보지 않습니다. 과거 월 누적 업로드 파일은 현재 월 비교 계산에만 사용하며 최신 기본값으로 등록하지 않습니다.

프로젝트 운영에서도 같은 정책을 적용합니다. 배포나 문서 갱신 시 업로드 최신값 등록 정책이 README, runbook, 배포본에 동일하게 남아 있는지 확인하고, public GitHub에는 원본 업로드 파일이나 민감한 실적 파일을 커밋하지 않습니다.

## 제한 배포 운영

링크를 받은 대상자에게만 제한적으로 배포할 때는 앱 URL만 공유하지 말고 접속 비밀번호도 별도 채널로 공유합니다. 링크가 전달될 수 있으므로 비밀번호를 함께 두는 것이 최소 보호 장치입니다.

`127.0.0.1` 주소는 로컬 PC 미리보기 전용입니다. 이 주소는 같은 PC에서만 접속할 수 있으므로 외부 대상자에게 공유할 배포 링크로 사용할 수 없습니다. 링크 제한 배포를 실제 운영하려면 Streamlit Community Cloud, Render, Azure, 사내 서버 등 상시 실행되는 배포 환경에 올리고 해당 환경의 Secrets에 접속 비밀번호를 설정합니다.

로컬에서만 미리볼 때는 아래 명령으로 서버를 실행합니다. 이 방식은 터미널이 열려 있는 동안만 서버가 유지됩니다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start_streamlit_server.ps1
```

서버 상태는 아래 명령으로 확인합니다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\check_streamlit_server.ps1
```

배포 전 확인 사항은 다음과 같습니다.

- 배포 환경의 Secrets 또는 환경변수에 `APP_ACCESS_PASSWORD`를 설정합니다.
- 비밀번호 평문 저장을 피하려면 `APP_ACCESS_PASSWORD_SHA256`에 SHA-256 해시값을 설정합니다.
- 실제 비밀번호는 `.streamlit/secrets.example.toml`이나 README에 적지 않습니다.
- 같은 배포 URL을 유지하고, 앱 수정 후 재배포해 기존 링크 사용자에게 업데이트가 반영되도록 운영합니다.
- 외부 공유 전 `outputs` 폴더의 Excel 리포트에 민감정보가 없는지 확인합니다.

## 입력 파일 준비 방법

입력 파일은 CSV 또는 XLSX로 준비합니다. 입력표는 사용자가 관리하는 영업일정 행만 포함해야 하며, 툴이 날짜를 추가하지 않습니다.

필수 컬럼은 아래와 같습니다.

```text
date
day_name
business_day_no
is_close_day
close_type
sales_target_daily
recognized_target_daily
sales_actual_cum
recognized_actual_cum
memo
```

준비 시 확인할 사항은 다음과 같습니다.

- `date`와 `business_day_no`는 중복 없이 입력합니다.
- `business_day_no`는 오름차순이어야 합니다.
- `is_close_day`만 마감일 판단 기준으로 사용합니다.
- `day_name`은 표시용이며 요일 자동 추론에 사용하지 않습니다.
- `sales_target_daily`, `recognized_target_daily`는 누락 없이 입력합니다.
- 기준일까지의 `sales_actual_cum` 또는 `recognized_actual_cum`은 선택 metric에 맞게 입력합니다.
- 기준일 이후 actual_cum은 비워둘 수 있습니다.
- 개인정보 또는 민감정보는 어떤 컬럼에도 입력하지 않습니다.

## 과거 월 누적 데이터 준비 방법

과거 월 누적 데이터는 선택 입력입니다. 현재 입력 파일과 같은 필수 컬럼을 사용하되 여러 월의 행을 한 파일에 이어 붙입니다.

준비 시 확인할 사항은 다음과 같습니다.

- `date`의 연월을 기준으로 과거 월을 구분합니다.
- `business_day_no`는 각 월 안에서 1부터 다시 시작합니다.
- 완료된 월은 가능한 한 모든 영업일의 누적 실적을 채웁니다.
- 중간 누락일이 있어도 앱은 같은 영업일차 이하의 가장 최근 누적 실적을 비교 대상으로 사용합니다.
- 과거 월별 최종 달성률은 해당 월의 마지막 누적 실적과 월 목표 합계로 계산됩니다.
- 과거 데이터는 현재 월 예측을 대체하지 않고, 현재 월이 과거 일반 범위보다 낮은지/높은지 보는 보조 기준입니다.

해석 순서는 다음을 권장합니다.

1. 현재 누적 달성률과 같은 영업일차의 과거 중앙값을 비교합니다.
2. 현재 흐름이 과거 하위 25% 아래인지, 상위 25% 위인지 확인합니다.
3. 과거 보정 예상 범위를 F1/F2/F3 예상과 비교합니다.
4. 과거 기준 예상이 F 모델보다 낮으면 보수적 리스크 설명을 추가합니다.
5. 과거 기준 예상이 F 모델보다 높으면 초과분 관리, 품질 리스크, Stretch 전환 가능성을 함께 봅니다.

## 기준일 선택 방법

기준일은 입력 파일의 `date` 컬럼에 존재하는 날짜만 선택합니다. 선택한 metric의 누적 실적이 기준일까지 채워져 있어야 하며, 기준일 당일 actual_cum이 비어 있으면 계산할 수 없습니다.

Streamlit 앱은 입력표에서 오늘보다 앞선 마지막 영업일을 기본 기준일로 매일 갱신합니다. 운영자는 필요하면 입력표에 있는 다른 기준일을 선택할 수 있으며, 선택한 기준일까지 선택 metric의 actual_cum을 입력한 뒤 계산합니다.

## sales / recognized metric 선택 방법

`sales`는 `sales_target_daily`와 `sales_actual_cum`을 사용합니다. `recognized`는 `recognized_target_daily`와 `recognized_actual_cum`을 사용합니다.

두 metric은 동일한 날짜표와 마감일 표시를 공유하지만 목표와 누적 실적은 별도로 계산됩니다. 판매실적 보고와 인정실적 보고가 다르면 각각 실행해 결과를 비교합니다.

## F1/F2/F3 해석법

- `F1`은 기준일까지의 누적 달성률을 잔여 모든 입력일에 동일하게 적용한 기본 예측입니다.
- `F2`는 직전 2개 완료 마감회차의 실적/목표 비율을 잔여 모든 입력일에 적용한 예측입니다. 완료 마감회차가 부족하면 F1 결과로 fallback합니다.
- `F3`는 기준일까지의 마감일 달성률과 비마감일 달성률을 분리해 잔여 마감일과 비마감일에 각각 적용한 예측입니다. 데이터가 부족하면 F2 또는 F1로 fallback합니다.

F1은 현재 누적 흐름, F2는 최근 마감회차 흐름, F3는 마감일과 비마감일의 성격 차이를 보는 관점입니다.

## P1/P2/P3 해석법

- `P1`은 모든 잔여 입력일에 목표 비중대로 상향 필요분을 배분합니다.
- `P2`는 잔여 마감일에 우선 배분합니다. 잔여 마감일이 없으면 `NOT_APPLICABLE`이 될 수 있습니다.
- `P3`는 잔여 비마감일에 우선 배분합니다. 잔여 비마감일이 없으면 `NOT_APPLICABLE`이 될 수 있습니다.

프로비전 결과의 `required_uplift`는 월 목표 달성을 위해 잔여 목표를 얼마나 상향해야 하는지 나타냅니다. `forecast_after_provision`은 해당 상향안을 반영한 뒤의 예상 실적입니다.

## 3x3 시나리오 매트릭스 해석법

3x3 시나리오 매트릭스는 F1/F2/F3 예측모델과 P1/P2/P3 프로비전 전략을 모두 조합한 결과입니다.

각 셀은 다음 형식으로 표시됩니다.

```text
forecast_after_provision / risk_level / status
```

해석 순서는 다음을 권장합니다.

1. F1, F2, F3별 기본 예측 차이를 확인합니다.
2. 같은 F 모델 안에서 P1, P2, P3의 `status`와 위험등급을 비교합니다.
3. `CAPACITY_LIMITED`, `CALCULATION_ERROR`, `NOT_APPLICABLE`이 있는 셀은 임원 보고용 확정안으로 바로 사용하지 않습니다.
4. 가장 보수적인 F 모델에서도 목표 달성 가능성이 있는지 확인합니다.
5. 선택 시나리오 상세에서 일자별 수정 목표표를 확인합니다.

## 위험등급 해석

위험등급은 예측 달성률, 상향 필요분, 프로비전 상태를 함께 반영합니다.

| 등급 | 의미 |
| --- | --- |
| `Green` | 예측 달성률이 100.0% 이상이고 상태가 `OK` 또는 `NO_GAP`입니다. |
| `Yellow` | 예측 달성률이 95.0% 이상이거나 상향 필요분이 잔여 목표의 5.0% 이하입니다. |
| `Red` | 예측 달성률이 90.0% 이상이거나 상향 필요분이 잔여 목표의 15.0% 이하입니다. |
| `Black` | 고위험, 계산 제한, 또는 위 기준을 충족하지 못하는 상태입니다. |
| `N/A` | 해당 프로비전 전략을 적용할 수 없습니다. |

`CAPACITY_LIMITED` 또는 `CALCULATION_ERROR`는 위험등급이 `Black`으로 표시됩니다. `NOT_APPLICABLE`은 `N/A`로 표시됩니다.

## 다음 마감 필요실적 해석

다음 마감일은 기준일 이후 입력표에 존재하는 `is_close_day=True` 행 중 가장 빠른 날짜입니다. 요일이나 날짜 패턴으로 추론하지 않습니다.

`next_close_required`는 다음 마감일까지 누적 목표를 회복하기 위해 기준일 현재 누적 실적 대비 추가로 필요한 실적입니다.

```text
next_close_required = max(0, next_close_target_cum - current_actual_cum)
```

다음 마감일이 입력표에 없거나 기준일 actual_cum이 비어 있으면 계산 불가로 해석합니다.

## CAPACITY_LIMITED 해석

`CAPACITY_LIMITED`는 cap rate 때문에 필요한 상향액을 모두 배분하지 못했다는 뜻입니다.

기본 cap rate는 다음과 같습니다.

- 마감일: 기존 목표의 1.30배
- 비마감일: 기존 목표의 1.50배

이 상태는 목표 달성이 가능하다는 뜻이 아닙니다. 임원 보고에서는 “현 cap 기준으로는 목표 달성에 필요한 상향 배분을 모두 담지 못함”으로 설명하고, cap 조정, 추가 영업일정 입력, 목표 재검토 중 어떤 조치가 필요한지 함께 제시합니다.

## 임원 보고 시 주의사항

- 가장 높은 예측값만 보고하지 말고 F1/F2/F3 범위를 함께 제시합니다.
- `is_close_day`가 사용자가 지정한 값임을 명확히 합니다.
- `CAPACITY_LIMITED`, `CALCULATION_ERROR`, `NOT_APPLICABLE` 상태는 별도 주석으로 설명합니다.
- 금액은 억 원 기준 소수점 1자리로 표시합니다.
- 달성률은 `%` 기준 소수점 1자리로 표시합니다.
- 다음 마감 필요실적은 다음 마감일까지의 누적 목표 회복 필요분으로 설명합니다.
- 프로비전 결과는 확정 실적이 아니라 잔여 목표 상향 시나리오입니다.

## 실데이터 보안 주의사항

- 원본 입력 파일은 수정하지 않습니다.
- 실제 고객명, 전화번호, 주소, 상세 계약번호, 주민번호 등 개인정보 또는 민감정보를 저장하지 않습니다.
- 고객 식별 정보는 `memo`, `close_type`, 파일명, Excel 리포트, 로그에도 남기지 않습니다.
- 샘플 데이터와 테스트 데이터는 익명화된 집계 값만 사용합니다.
- 과거 월 누적 데이터는 월별 추세와 최종 성과를 포함하므로 단월 입력보다 민감하게 취급합니다.
- 과거 월 업로드 파일은 앱 계산에만 사용하고 별도 파일로 저장하지 않습니다.
- 실데이터를 배포 앱에서 사용할 때는 public GitHub에 데이터 파일을 올리지 않습니다.
- 공유 비밀번호 방식은 링크 제한 수준의 보호이므로, 대상자가 늘어나거나 데이터 민감도가 올라가면 private repo, 사용자별 인증, 비밀번호 주기 교체, 업로드 파일 보관 금지 정책을 적용합니다.
- `outputs` 폴더의 Excel 리포트를 외부 공유하기 전에 민감정보 포함 여부를 확인합니다.
- 실데이터가 필요한 경우에도 집계 단위로만 입력하고 원본 파일은 별도 보안 정책에 따라 관리합니다.
